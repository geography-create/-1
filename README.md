# 한여울시 도시 설계 — 누구의 도시를 만들 것인가

고등학교 **「도시의 미래 탐구」**(2022 개정) 수행평가용 학생 웹앱입니다. 학생은 가상 도시
한여울시의 9칸×9칸 격자 지도 위에서 예산 안에 도시 시설을 배치하고, 생활권별로 갈린
결과를 근거로 세 가지 질문에 서술로 답합니다.

- **성취기준** [12도탐04-01] 지속가능성과 회복력이 높은 도시가 되기 위한 요건에 대해
  토의하고 이와 관련한 도시 계획 및 도시 혁신 사례를 탐구한다.
  (연계) [12도탐04-02] 도시의 공공성과 도시에 대한 권리를 이해하고, 시민 참여를 통해
  도시 문제를 해결하는 과정을 탐구한다.
  (연계) [12도탐03-01] 도시의 환경 문제와 재난을 공간 정의의 관점에서 분석하여 해결
  방안을 탐색한다.
- **평가 방법** 서술·논술 + 공간적 의사 결정 활동 + 교사 관찰 및 기록
- **배점** 서술 3문항 × 5점 = 15점
- **AI 활용** 평가 계획서에 따라 **X**. 앱에 AI 기능은 들어 있지 않습니다.

## 학생 활동 흐름

1. **과제 안내** — 과제와 채점 기준을 처음부터 공개합니다. 네 생활권의 서로 다른 초기
   조건을 확인합니다.
2. **배치** — 예산 100(억) 안에서 시설 13종을 격자에 놓습니다. 하천 칸에는 놓을 수
   없고, 일부 시설에는 선행 조건이 있습니다(예: 산업단지는 같은 생활권에 하수·빗물
   처리시설이 먼저 있어야 함).
3. **결과** — 생활권별 사회·경제·환경 지수, 생활권 간 격차 판정, 3년차 집중호우와
   6년차 폭염의 결과, 비인간 존재(하천 생태·도시 숲·도시 속 동물) 지표를 봅니다.
4. **서술** — 세 문항에 답합니다. 문항마다 채점 기준과 자기점검 항목이 붙어 있습니다.
5. **제출** — 반·번호·이름과 함께 전송하거나 인쇄합니다.

## 계산 규칙

무작위 요소가 **없습니다.** 같은 배치는 반 전체에서 언제나 같은 결과를 냅니다.

| 항목 | 규칙 |
| --- | --- |
| 생활권 지수 | 초기 조건 + 놓은 시설 효과 + 보정 + 재난 피해 |
| 보정 | 하천 인접 시설(±2), 녹지 연결(+2), 논·습지 훼손(−2), 주거-산업 인접(−2), 쇼핑몰의 상가 잠식, 교통 소외(−2), 공공서비스 소외(−2) |
| 종합 생활 편익 | 사회 × 0.4 + 경제 × 0.3 + 환경 × 0.3 |
| 생활권 격차 | 최고−최저가 3 이상 **경계**, 5 이상 **위험** |
| 3년차 집중호우 | 저지대 칸 수 ÷ 4(올림)만큼의 물 받이 능력이 없으면 사회 −3, 경제 −3, 환경 −1 |
| 6년차 폭염 | 생활권 칸 수 ÷ 6(올림)만큼의 녹지가 없으면 사회 −2, 환경 −1 |
| 하천 생태 | 하천과 맞닿은 칸에 무엇을 놓았는지로 가감 |
| 도시 숲 | 가장 크게 이어진 녹지 덩어리 크기 |
| 도시 속 동물 | 하천까지 녹지로 이어진 칸 수 |

수치를 바꾸고 싶으면 `src/data/city.ts`(지형·생활권·예산)와
`src/data/facilities.ts`(시설 비용·효과), `src/lib/engine.ts`(보정·재난 규칙)만 고치면
됩니다. 채점 기준 문구는 `src/data/rubric.ts`에 있습니다.

## 교사용 진행 안내

배포 주소 뒤에 `?teacher=1`을 붙여 접속하면(예: `https://example.com/?teacher=1`) 화면
오른쪽 아래에 **교사용 진행 안내** 버튼이 나타납니다. 차시 배분, 채점할 때 눈여겨볼
지점, 시설 수치표 전체를 볼 수 있습니다. **학생에게 배포하는 링크에는 이 파라미터를
붙이지 마세요** — 붙이지 않으면 버튼 자체가 보이지 않습니다.

## 개인정보

- 배치와 서술은 **학생 브라우저 안(localStorage)에만** 자동 저장됩니다. 새로고침하거나
  브라우저를 닫아도 이어서 쓸 수 있습니다.
- 반·번호·이름은 **마지막 제출 단계에서만** 입력하며, 아래 결과 수합이 설정된 경우에만
  선생님의 구글 시트로 전송됩니다.
- 공용 기기라면 제출 후 상단 **처음부터 다시**로 기록을 지우게 안내하세요.
- 시크릿 모드나 저장소가 차단된 환경에서는 자동 저장이 되지 않습니다.

## 개발

```bash
npm install
npm run dev              # 개발 서버
npm run build            # 프로덕션 빌드
npm run build:standalone # 파일 하나로 된 오프라인 버전 (dist-standalone/index.html)
npm run lint             # oxlint
```

`build:standalone`은 배포 없이 파일 하나로 열어볼 수 있는 버전을 만듭니다. JS·CSS가 전부
`dist-standalone/index.html` 한 파일에 들어가 더블클릭만으로 브라우저에서 열립니다.
인터넷이 불안정한 교실에서 USB로 돌리거나 동료 교사에게 미리보기를 보낼 때 씁니다.
다만 구글 시트 제출은 여전히 인터넷이 있어야 동작하고, `.env.local`의 웹훅 URL이 빌드
시점 그대로 파일에 박히니 배포용으로 계속 쓰지는 마세요.

## 배포

이 저장소의 GitHub Pages 워크플로(`.github/workflows/deploy-pages.yml`)는 기본 브랜치
(`claude/lesson-plan-webapp-q6trca`, 승기천 정비 시뮬레이터)를 배포하도록 되어 있습니다.
저장소 하나에 Pages 사이트는 하나뿐이라 이 앱을 같은 주소로 올리면 승기천 앱이 덮어
쓰입니다. 이 앱을 Pages로 올리려면 워크플로의 `branches:` 한 줄을 이 브랜치 이름으로
바꾸거나, 위의 `build:standalone`으로 만든 단일 파일을 쓰세요.

## 교사용 결과 수합 설정 (선택)

제출 화면의 "작성 완료·제출"을 누르면 반·번호·이름, 배치 내역, 생활권별 최종 지수,
생활권 격차와 수준, 비인간 지표, 재난 결과, 서술 3문항이 구글 시트에 한 줄씩 쌓입니다.
별도 서버 없이 구글 계정만으로 설정할 수 있습니다.

1. 구글 드라이브에서 새 스프레드시트를 만듭니다 (예: "한여울시 수행평가 결과").
2. 메뉴에서 **확장 프로그램 > Apps Script**를 엽니다.
3. 기본으로 열려 있는 코드를 지우고, 이 저장소의
   [`google-apps-script/doPost.js`](./google-apps-script/doPost.js) 내용을 그대로
   붙여넣습니다.
4. 오른쪽 위 **배포 > 새 배포**를 클릭합니다.
   - 유형: **웹 앱**
   - 실행 계정: **나**
   - 액세스 권한: **모든 사용자**
5. 배포 후 발급되는 `.../exec`로 끝나는 URL을 복사합니다.
6. 프로젝트 루트에 `.env.local` 파일을 만들고 아래처럼 붙여넣습니다 (`.env.example` 참고).

   ```
   VITE_SHEET_WEBHOOK_URL=여기에_복사한_URL
   ```

7. `npm run build`로 다시 빌드해 배포하면, 그 빌드로 접속한 학생들의 제출이 같은 시트에
   쌓입니다.

**주의할 점**

- 브라우저에서 Apps Script 웹 앱으로 보내는 요청은 CORS 제약 때문에 응답을 확인할 수
  없습니다. 학생 화면에는 "제출을 보냈다"는 안내만 뜨므로, 실제 기록 여부는 선생님이
  시트를 열어 확인해야 합니다. **수업 전에 반드시 한 번 테스트해 보세요.**
- `VITE_SHEET_WEBHOOK_URL`을 설정하지 않으면 제출은 그 기기에만 표시되고 시트로는
  전송되지 않습니다. 이 경우 학생에게 인쇄 제출을 안내하세요.
- URL을 설정한 순간부터 이름 등 개인정보가 외부(구글 시트)로 전송되므로, 학교의
  개인정보 처리 방침에 맞게 사용해 주세요.
